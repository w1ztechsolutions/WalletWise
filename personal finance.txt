## 1. App Overview

Build **WalletWise**, a personal finance management web app for tracking transactions, accounts, budgets, and analytics. ## 3. Security Requirements (implement all)

1. **Authentication & session management** â€” use the platform's built-in authentication (email/password and social login). Never build custom auth, never store passwords or tokens in app code or localStorage.
2. **Strict per-user data isolation** â€” every data fetch (transactions, budgets, categories, accounts) must filter by the authenticated user's identity (filter on the record's created_by field matching the current user's email/id). No page may ever list another user's records. React Query cache keys include the user identity so cached data never leaks between users.
3. **Row-Level Security (RLS)** â€” configure RLS on every entity so that, at the database level, users can read, create, update, and delete ONLY their own records. Server-side enforcement, not just UI filtering. Only admins may manage user records.
4. **No secrets in the frontend** â€” API keys, tokens, and credentials only in server-side environment secrets, never in client code, URLs, or entity fields.
5. **Private file uploads** â€” any user-uploaded file (receipts, Excel imports) goes to private storage behind permissioned access, with signed, time-limited download URLs. Never public storage for user data.
6. **Input validation & sanitization** â€” validate and sanitize all user input (amounts must be positive numbers, dates valid, IDs validated before use); user input is never inserted directly into queries (prevent injection).
7. **Minimal data exposure** â€” store only the last 4 digits or a reference for account numbers; never full account or card numbers.
8. **Server-side-only privileged operations** â€” anything that acts on behalf of other users (push notifications, bulk admin actions) must run server-side with the service role, never from the browser.
9. **Error handling without information leaks** â€” show friendly generic errors in the UI; log full details server-side only.
10. **Email hygiene** â€” emails sent from the app use the platform's email service; user-supplied text is never routed directly into recipient fields (anti-abuse protection).

## 4. Pages & Features

### Layout (all pages)
- Top bar with hamburger menu button (all screen sizes) that opens a slide-in sidebar: app name "WalletWise" (text only, no logo image), current user's name and email, navigation links (Dashboard, Transactions, Accounts, Budgets, Analytics, Settings), and a Sign Out button.
- **Mobile (below tablet breakpoint): fixed bottom navigation bar** with icon + label for the six sections, active item highlighted in the primary color; page content gets extra bottom padding so nothing is hidden behind the bar.
- Slide-in sidebar with dark overlay backdrop; closes on navigation, overlay tap, or X button.

### Dashboard (home, "/")

- Delete confirmation.

- Account cards: type icon, name, institution, masked account number, color-themed card with decorative background, current balance, active status; hover edit/delete.
- Add/Edit dialog: name, type (with icon + suggested institution presets like FNB, Standard Bank, MTN, Airtel), institution, account number (masked), balance, color picker, notes, active toggle.

### Analytics ("/analytics")
- Stat cards: total income, total expenses, net balance, savings rate.

## 6. Data & Query Architecture

- Data fetching via React Query (useQuery) with user-scoped cache keys; mutations via useMutation with cache invalidation.
- All list queries filtered by the current user's identity and sorted sensibly (transactions by date desc, accounts by created date desc).
- Never seed or display another user's data; a new user starts with an empty but welcoming dashboard (empty states everywhere).
- Currency formatting via a single shared helper with sensible defaults (e.g. Zambian Kwacha or user-locale), reused by every page.

## 7. Acceptance Criteria

- A logged-in user sees ONLY their own transactions, budgets, categories, and accounts on every page, enforced both in queries and at the database (RLS).
- Two different users on the same app see completely different data.
- Every create, edit, and delete works from the UI and persists after reload.
- Excel import creates only transactions/budgets belonging to the importing user.
- On a phone browser, the bottom nav is always visible and tappable; content never hides behind it.
- On desktop, the hamburger menu opens the sidebar; navigation works with one tap at every breakpoint.
